# KESMO Starter Kit

**Version 1.1.0**

The reusable website foundation for KESMO web tools.

> Precision made simple.

## Overview

The KESMO Starter Kit provides the shared structure, design system, branding, accessibility features, search metadata, supporting pages, reusable components, and documentation used by future KESMO projects.

Every new KESMO tool begins with this repository instead of being built from scratch.

The KESMO Pricing Calculator was the first completed KESMO product and served as the original design and quality benchmark. The Starter Kit is now the single source of truth for shared KESMO code, branding, architecture, and improvements.

## Current Status

The Starter Kit is ready to serve as the foundation for future KESMO tools.

Version 1.1.0 introduces a standardized shared page architecture built around reusable Header, Hero, and Footer components.

The current shared components are:

* Header
* Hero
* Footer

These components are generated by `components.js` and used across the standard KESMO pages:

* Home
* About
* Privacy
* 404

The Starter Kit remains a development foundation rather than a public-facing KESMO tool.

## Shared Architecture

Shared page components are managed by `components.js`.

The standard page structure is:

```text
Page
├── Shared Header
├── Shared Hero
├── Page-specific content
└── Shared Footer
```

Each page includes component placeholders:

```html
<div id="site-header"></div>

<main id="main-content">
  <div
    id="page-hero"
    data-eyebrow="..."
    data-title="..."
    data-description="..."
  ></div>

  <!-- Page-specific content -->
</main>

<div id="site-footer"></div>
```

The Hero component supports the following data attributes:

* `data-eyebrow`
* `data-title`
* `data-description`
* `data-note`

Page-specific text remains in the HTML while shared structure and markup remain centralized in `components.js`.

## Shared Development Workflow

The Starter Kit is the single source of truth for shared KESMO improvements.

When an improvement benefits more than one KESMO tool, follow this workflow:

1. Improve the Starter Kit.
2. Verify the improvement in the Starter Kit.
3. Apply the improvement to existing KESMO tools.
4. Use the updated Starter Kit as the foundation for future tools.

If an improvement is first proven inside an existing KESMO tool, copy it back into the Starter Kit before treating it as a shared standard.

The live GitHub repository and this README are the development source of truth. Repository contents take precedence over previous notes or chat history.

## Design Standards

Every KESMO tool should preserve the shared KESMO design language unless a project has a compelling reason to extend it.

Shared standards include:

* Mobile-first responsive design
* Consistent KESMO branding
* Clear visual hierarchy
* Readable typography
* Consistent spacing
* Accessible color contrast
* Visible keyboard focus states
* Semantic HTML
* Fast loading
* Minimal dependencies
* Professional supporting pages
* Consistent Header, Hero, and Footer structure

The Pricing Calculator remains the first completed product and an important quality reference, while the Starter Kit remains the source of truth for shared implementation.

## Accessibility Standards

Every KESMO project should include:

* A working skip link
* A unique page heading
* Semantic page landmarks
* Keyboard-accessible navigation
* Visible focus styles
* Accessible link and button labels
* Meaningful heading order
* Reduced-motion support
* High-contrast support where practical
* Responsive layouts without horizontal overflow

Shared components should not create duplicate headings, skip links, or landmarks.

## Search and Social Standards

Every public KESMO page should include:

* A descriptive page title
* A useful meta description
* A canonical URL
* Open Graph metadata
* X/Twitter Card metadata
* Structured data where appropriate
* A favicon
* A social sharing image
* Accurate `robots.txt`
* Accurate `sitemap.xml`

The custom `404.html` page should not be included in the sitemap.

## Required Before Publishing

Before releasing a KESMO tool built from this Starter Kit:

* [ ] Change `robots.txt` to allow search indexing.
* [ ] Update `sitemap.xml` with the new tool's URLs.
* [ ] Replace all `KESMO-Starter-Kit` URLs with the new repository URL.
* [ ] Update the `<base>` tag in `404.html`.
* [ ] Replace the homepage content with the tool interface.
* [ ] Review the Privacy Policy for tool-specific features.
* [ ] Verify the custom 404 page.
* [ ] Test GitHub Pages deployment.
* [ ] Confirm the All KESMO Tools destination is live.
* [ ] Confirm there are no broken shared navigation links.

## Copying the Starter Kit

Follow this checklist every time you create a new KESMO tool.

### 1. Create the Repository

* [ ] Create a new public GitHub repository.
* [ ] Copy the entire KESMO Starter Kit into the new repository.
* [ ] Enable GitHub Pages.

---

### 2. Update `components.js`

Update the `KESMO_CONFIG` object.

* [ ] `repositoryName`
* [ ] `projectName`
* [ ] `version`
* [ ] `toolHomeUrl`
* [ ] `kesmoHomeUrl`
* [ ] `supportEmail`
* [ ] `logoPath`

`toolHomeUrl` normally remains:

```text
index.html
```

`kesmoHomeUrl` should point to the central KESMO website:

```text
https://kesmoworks.github.io/
```

---

### 3. Update Navigation Labels

Update project-specific navigation text where needed.

For example:

```text
Home
```

may become:

```text
Pricing Calculator
```

The About, Privacy, and All KESMO Tools links should remain consistent across KESMO projects unless a project requires different navigation.

---

### 4. Update Shared Hero Content

Each standard page should use the shared Hero placeholder.

Review:

* [ ] `data-eyebrow`
* [ ] `data-title`
* [ ] `data-description`
* [ ] `data-note`, when applicable

Confirm that old hard-coded Hero markup has been removed.

---

### 5. Update Search Metadata

Every public page should receive:

* [ ] Correct page title
* [ ] Correct meta description
* [ ] Correct canonical URL
* [ ] Correct Open Graph URL
* [ ] Correct Open Graph image
* [ ] Correct X/Twitter Card information
* [ ] Correct structured data

Pages to review:

* [ ] `index.html`
* [ ] `about.html`
* [ ] `privacy.html`

---

### 6. Replace Starter Kit Content

* [ ] Replace the homepage with the new tool.
* [ ] Update the About page for the new tool.
* [ ] Review the Privacy Policy for the tool's actual behavior.
* [ ] Update the social sharing image if appropriate.
* [ ] Remove Starter Kit-specific instructions from public-facing content.

---

### 7. Update Search Files

#### `robots.txt`

Before publishing a public KESMO tool, change:

```text
Disallow: /
```

to:

```text
Allow: /
```

#### `sitemap.xml`

* [ ] Replace every Starter Kit URL with the new repository URL.
* [ ] Verify that `404.html` is not included.
* [ ] Verify that every listed page is publicly available.

---

### 8. Update `404.html`

* [ ] Update the `<base>` path to the new repository.
* [ ] Confirm it loads `components.js`.
* [ ] Confirm it uses the shared Header.
* [ ] Confirm it uses the shared Hero.
* [ ] Confirm it uses the shared Footer.
* [ ] Confirm all recovery links work.

Example:

```html
<base href="https://kesmoworks.github.io/NEW-REPOSITORY/">
```

---

### 9. Test Everything

Verify:

* [ ] Home page
* [ ] About page
* [ ] Privacy page
* [ ] Custom 404 page
* [ ] Shared Header
* [ ] Shared Hero
* [ ] Shared Footer
* [ ] Mobile layout
* [ ] Desktop layout
* [ ] Keyboard navigation
* [ ] Skip link
* [ ] Footer links
* [ ] Email link
* [ ] All KESMO Tools link
* [ ] Social sharing image
* [ ] Favicon

---

### 10. Final Review

Confirm:

* [ ] No unintended Starter Kit text remains.
* [ ] No placeholder content remains.
* [ ] No duplicate skip links remain.
* [ ] No hard-coded shared components remain.
* [ ] No broken links remain.
* [ ] No console errors appear.
* [ ] Accessibility still works.
* [ ] Search metadata is accurate.
* [ ] The tool feels production-ready.
* [ ] The README accurately reflects the repository.

Only after every applicable item above is complete should the new KESMO tool be considered ready for publication.
